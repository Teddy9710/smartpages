# SmartPages Agent 可执行工作流设计

## 1. 背景与目标

SmartPages 当前将真实网页操作记录为供人阅读的操作文档。本项目扩展这条链路：用户示范一次操作后，SmartPages 同时生成供人阅读的 SOP 和供 Agent 执行的结构化工作流。用户可将工作流交给 Codex、Claude Code 等本地 Agent，由 Agent 调用 SmartPages，在用户当前浏览器会话中按流程执行。

产品定位是：将一次人工操作同时变成“人能读的 SOP”和“Agent 能执行的 Workflow”。首要场景是企业后台 SOP 自动执行、客服标准操作、测试与 Bug 复现，以及没有稳定 API 的重复录入任务。

MVP 不试图成为通用浏览器 Agent。它只在已录制的网站和流程范围内执行，并允许页面结构发生轻微变化。

## 2. 已确认的产品决策

- 首批支持本地桌面 Agent。
- 每次生成 Markdown 与 SmartPages JSON 两个关联产物。
- 普通浏览、点击和填写可自动执行；提交、发送、删除、支付和权限变更逐步确认。
- 页面轻微变化时允许基于语义恢复元素定位。
- 使用本机 MCP Bridge，不部署云端执行服务。
- MCP Server 与 Native Messaging Host 合并为一个本地程序 `smartpages-mcp`，减少安装和维护成本。

## 3. 总体架构

```mermaid
flowchart LR
  Agent["本地 Agent"] -->|"MCP tools"| Bridge["smartpages-mcp / bridge"]
  Bridge <-->|"Chrome Native Messaging"| Extension["SmartPages 扩展"]
  Extension <-->|"定位、执行、读取状态"| Page["用户当前网页"]
```

### 3.1 本地 Agent

Agent 负责理解用户目标、选择工作流、提供非敏感变量并调用 MCP 工具。Agent 不获得任意 JavaScript 执行能力，也不绕过扩展直接控制网页。

### 3.2 `smartpages-mcp` Bridge

Bridge 安装在用户电脑上，由 Agent 按需通过标准输入输出启动。它承担两项职责：

1. 暴露 MCP 工具。
2. 通过 Chrome Native Messaging 与 SmartPages 扩展传递经过验证的协议消息。

Bridge 不监听公网端口，不保存浏览器登录态，也不解释具体网页业务。

### 3.3 SmartPages 扩展

扩展负责工作流存储、标签页选择、元素定位、动作执行、风险确认、状态恢复和执行日志。现有 `content/recorder.js` 继续负责采集操作，新增的回放执行器与录制器保持独立边界。

### 3.4 可选云服务

云服务不属于 MVP。未来的团队流程库只负责同步经过授权的工作流；实际网页操作仍在本地完成。

## 4. 双产物模型

一次录制生成：

- `<name>.md`：给人阅读、编辑、分享和审核。
- `<name>.smartpages.json`：给 Agent 和扩展验证、规划和执行。

两个产物共享 `workflowId` 和 `workflowVersion`。Markdown 中展示流程标识和 JSON 文件名，但 Markdown 不是执行事实来源。用户修改自然语言文档不会隐式改变机器工作流；结构化步骤必须通过 SmartPages 编辑器更新并重新导出。

## 5. 工作流 Schema

顶层字段至少包含：

```json
{
  "schemaVersion": "1.0",
  "workflowId": "create-customer",
  "workflowVersion": 1,
  "title": "创建客户",
  "allowedOrigins": ["https://example.com"],
  "variables": [
    { "name": "customerName", "required": true, "secret": false }
  ],
  "steps": []
}
```

每个步骤包含：

- `id`：工作流内稳定且唯一的步骤标识。
- `action`：允许的动作类型。
- `target`：录制选择器和语义定位信息。
- `input`：字面值或变量引用，不保存密码、Token 或验证码。
- `precondition`：执行前 URL、可见元素或页面状态。
- `postcondition`：执行后必须满足的可验证状态。
- `risk`：`low`、`medium` 或 `high`。
- `description`：供人和 Agent 理解的简短说明，不参与最终定位裁决。

MVP 支持七类动作：`navigate`、`click`、`input`、`select`、`scroll`、`wait`、`assert`。任意 JavaScript、文件上传、下载、跨标签页编排和循环不在 MVP 范围内。

## 6. MCP 工具接口

MVP 暴露以下工具：

- `list_workflows`：列出可用工作流的标识、版本、目标站点和变量摘要。
- `load_workflow`：加载并校验指定工作流，返回可执行摘要。
- `preview_run`：绑定变量并生成执行计划、风险步骤和缺失输入。
- `start_run`：创建运行并执行至完成、失败或需要交互。
- `resume_run`：在用户确认或补充输入后继续。
- `get_run_status`：读取当前步骤、状态、日志和待处理请求。
- `cancel_run`：安全终止执行。

MCP 返回结构化结果，不以自然语言字符串代替状态码。`runId` 用于关联整次执行，所有继续、查询和取消请求必须携带它。

## 7. 执行流程与状态机

执行前，扩展依次校验 Schema、协议版本、目标站点、变量和当前页面前置条件。通过后才进入运行状态。

```text
READY
  -> RUNNING
  -> WAITING_CONFIRMATION
  -> WAITING_INPUT
  -> FAILED
  -> COMPLETED
  -> CANCELLED
```

每个步骤按照以下顺序执行：

1. 检查 `precondition`。
2. 定位目标元素。
3. 计算风险等级，并在需要时请求用户确认。
4. 执行动作。
5. 检查 `postcondition`。
6. 写入不可变步骤结果，再进入下一步。

只有已通过后置条件的步骤才算完成。恢复执行从最后一个已验证步骤之后开始。

## 8. 语义定位恢复

扩展按照以下优先级定位元素：

1. 录制时保存的稳定选择器。
2. 稳定 `data-*` 属性和表单关联关系。
3. ARIA role 与 accessible name。
4. 可见文本、标签、占位符及邻近语义。
5. 录制页面快照与当前页面的候选匹配。

定位器产生一个置信度结果。唯一且高置信度时可以继续；存在多个候选或置信度低于阈值时进入 `WAITING_INPUT`。MVP 不允许通过坐标盲点来掩盖定位失败。

## 9. 安全与权限

- JSON 视为不可信输入，执行前必须通过严格 Schema 校验；未知动作和未知字段按协议规则拒绝。
- 工作流只允许访问 `allowedOrigins`。跨域导航立即暂停并提示用户。
- 密码、Token、验证码、支付信息等敏感值不进入导出文件或普通日志。
- `submit`、发送消息、删除、支付、权限修改等高风险动作在动作发生前由扩展界面逐步确认。
- 确认界面必须显示动作、目标站点、目标元素、将提交的数据摘要及不可逆影响。
- Bridge 仅接受登记的扩展 ID、兼容协议版本和当前会话令牌。
- MCP 不提供任意脚本执行、任意文件读取或绕过浏览器权限的工具。
- 用户拒绝确认、扩展断开或页面越界时安全停止。

## 10. 错误处理与执行报告

定位失败时尝试语义恢复；多候选时暂停；页面超时只允许有限重试。用户手动改变页面后，扩展重新检查当前步骤前置条件，不满足时暂停。

每次运行输出结构化报告，包括：

- 工作流和版本。
- 开始、结束时间和最终状态。
- 每一步的动作、结果和耗时。
- 是否使用语义恢复及其置信度。
- 用户确认、拒绝或补充输入事件。
- 失败代码、失败步骤、当前 URL 和脱敏诊断信息。
- 可选截图引用，不默认将截图传给 Agent 或外部服务。

## 11. UI 变化

SmartPages 侧边栏增加：

- “生成可执行工作流”选项。
- 变量识别与敏感字段检查。
- 工作流步骤编辑和风险标记。
- JSON 导出入口。
- 回放预览和扩展内手动回放入口。
- 运行状态、逐步确认、暂停和取消界面。

设置页增加本地 Bridge 连接状态、安装说明、扩展 ID 和协议版本信息。

## 12. 分阶段实施

### 阶段一：扩展内可执行工作流

- 定义 Schema 与版本策略。
- 将录制 Session 转换为结构化 Workflow。
- 实现 Markdown + JSON 双产物导出。
- 实现扩展内手动回放、七类基础动作、条件验证和基础日志。

### 阶段二：Agent 接入

- 实现 `smartpages-mcp` Bridge。
- 注册 Native Messaging Host。
- 实现 MCP 工具、会话协议、超时和取消。
- 提供 Windows 首版安装与卸载脚本，以及 Agent 配置示例。

### 阶段三：可靠性与安全体验

- 实现语义定位恢复和置信度策略。
- 实现逐步确认界面与敏感信息脱敏。
- 完善断线恢复和结构化执行报告。

文件上传、下载、跨标签页、循环、条件分支、定时执行和团队流程库明确推迟到后续版本。

## 13. 测试策略

- Schema 单元测试：合法、缺失、未知、越权和版本不兼容输入。
- Session 转换测试：录制步骤正确转换为动作、变量、条件和风险等级。
- 定位测试：选择器成功、选择器失效后的语义恢复、多候选和低置信度。
- 执行器测试：七类动作、前后置条件、超时、重试、取消与恢复。
- 安全测试：跨域阻断、危险动作确认、敏感字段脱敏、任意脚本拒绝。
- Bridge 协议测试：身份、版本、会话令牌、消息长度、断线与超时。
- 端到端测试：本地 Agent 加载示例流程，在测试页面执行并生成报告。

## 14. MVP 验收标准

- 一次录制能导出关联的 Markdown 和 JSON。
- JSON 能通过版本化 Schema 独立校验。
- 扩展可手动回放七类基础动作，并逐步验证结果。
- 本地 Agent 可通过 MCP 发现、预览、启动、继续、查询和取消流程。
- 页面轻微变化时可恢复唯一且高置信度的元素定位。
- 所有高风险动作都在扩展内于动作发生前确认。
- 跨域、定位歧义、用户拒绝、扩展断开和验证失败均安全停止。
- 完成一次运行后可获取结构化、脱敏的执行报告。
